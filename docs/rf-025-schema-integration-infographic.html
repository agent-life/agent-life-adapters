agent-life-adapters · RF-025 · scripts/run_integration_tests.sh

The integration fixture, made reproducible

The old gate followed a moving branch, generated random bytes, and wrote them into tracked files. The fix inverts every one of those: the fixture is a reviewed compatibility artifact, and the test command can only read it, regenerate it in a sandbox, and compare.

SCHEMA_COMMIT+ FIXTURE_SEED+ ALF 1.0.0+ pinned Python env ⇒ identical SHA-256, every run, every machine
01 · Authority

One lock file decides everything

scripts/integration-fixture.lock is the sole schema-revision authority. Changing format compatibility is a reviewed lock-file diff — never an implicit update from main or a latest tag.

scripts/integration-fixture.lock
# Reviewed inputs — every value is a release-owner decision
SCHEMA_REPOSITORY=https://github.com/agent-life/…-data-format.git
SCHEMA_COMMIT=a46bd2ada6c800dd17ca02939b481e283277217a
FIXTURE_ALF_FORMAT_VERSION=1.0.0
FIXTURE_SEED=20260730
GENERATOR_PYTHON_MINOR=3.14
GENERATOR_REQUIREMENTS_LOCK=scripts/…-requirements.lock
SCHEMA_COMMIT A full 40-char SHA, fetched by commit and detached. No branch, no tag, no git pull, no shared /tmp checkout.
FIXTURE_ALF_FORMAT_VERSION 1.0.0 — the ALF format version every shipping adapter writes. Not the CLI release version (v1.1.0).
FIXTURE_SEED Seeds random, Faker, and JSF; the generator also freezes the clock at 2026-01-01T00:00:00Z.
GENERATOR_PYTHON_MINOR + …REQUIREMENTS_LOCK Byte-determinism holds per interpreter minor + exact wheel set. Wheels are hash-pinned and installed with pip --require-hashes; the env verifier refuses to run on anything else.
alf-cli/fixtures/schema_version.txt is demoted to generated metadata. The regeneration workflow writes the locked commit into it; --check compares it against the lock. It is never an input, and nothing selects a schema revision from it.
02 · Modes

Three ways to obtain the pinned schemas

Every mode ends at the same place: a checkout verified to be exactly SCHEMA_COMMIT with a clean schemas/ tree. They differ only in how it gets there and what they may touch.

default

Fetch the pin

  • mktemp -d owns the checkout
  • git fetch --depth=1 origin $SCHEMA_COMMIT, then detach at FETCH_HEAD
  • Installs the hash-pinned wheels only if the env verifier fails
network allowed
--schema-dir <checkout>

Use your sibling checkout

  • HEAD must equal SCHEMA_COMMIT — mismatch fails, names both revisions
  • schemas/ must be porcelain-clean — a dirty schema tree is rejected
  • A bare schemas/ dir is not accepted: no provenance
network allowed
--offline --schema-dir

Air-gapped run

  • No pip, no git remotes, no clone/fetch/pull
  • Environment must already match the lock, or fail with setup guidance
  • Same pin + cleanliness verification as above
zero network
03 · The run

Everything happens inside the sandbox

A normal run — including the release gate — creates one temporary directory and never writes outside it. The worktree stays byte-for-byte untouched. Exactly one command may cross the boundary.

mktemp -d · temporary, isolated
  1. 1

    Verify the generator environment

    Interpreter minor and every locked package version must match. Online mode may install the pinned wheels first; offline mode must already be correct.

    mismatch → fail before generating
  2. 2

    Obtain + verify the schema checkout

    HEAD == SCHEMA_COMMIT, clean schemas/. The verified checkout is the only schema source from here on.

    wrong commit or dirty tree → fail
  3. 3

    Generate the canonical archive

    Seeded RNG, frozen clock, deterministic record IDs. Canonical JSON: sorted keys, LF, trailing newline. ZIP members in sorted order, DOS-epoch timestamps, fixed 0644, ZIP_STORED — no zlib variation.

  4. 4

    Validate against the pinned schemas

    Every member — including each JSONL memory record — validates against the Draft 2020-12 schemas from the verified checkout, before anything else consumes it.

    schema violation → fail, names the revision
  5. 5

    Prove it with the real binary

    cargo test runs alf validate against the temporary fixture (path passed via env vars) and writes a report under the sandbox: adapter commit, schema commit, Python + lock SHA, fixture SHA-256, verdict.

Repository worktree — tracked
alf-cli/fixtures/synthetic-agent.alf

The reviewed compatibility artifact. Fallback for plain cargo test.

alf-cli/fixtures/schema_version.txt

Generated metadata: the locked full commit, written at regeneration time.

default · --check · --offline  — read-only. May compare, never write.
--regenerate-fixture  — the only writer. Atomic, same-directory replace, after full validation passes.
Invariant: the two artifacts change together or not at all. A commit that updates one without the other cannot pass --check.
04 · Maintenance

Checking is not regenerating

Two explicitly separate workflows. The release gate uses the first; only a deliberate maintainer action uses the second.

--check

Is the committed fixture current?

Regenerates into the sandbox, then byte-compares both tracked artifacts against the fresh output.

PASSBoth files byte-identical — evidence is reproducible from HEAD.
STALENonzero exit; prints the locked revision and both SHA-256 values so the diff is reviewable.
--regenerate-fixture

Deliberately update the artifact

Completes generation, schema validation, and the Cargo proof in the sandbox first. Only then atomically replaces both tracked files — showing changed paths and hashes — and never touches unrelated worktree changes.

RULERuns only after a lock-file change was reviewed. It is never the release gate.
05 · Guarantees

What the design promises

  • Byte-identical output for identical inputs — provable by running twice and comparing SHA-256.
  • No moving refs, ever: no git pull, no main, no latest tag, no mutable shared /tmp checkout.
  • Normal runs leave the worktree untouched — reports and archives live only in the sandbox.
  • Offline means offline: zero network, git-remote, or package-manager calls.
  • Wrong pin fails loudly — expected and actual revisions are named before anything is generated.
  • Every report carries provenance: adapter commit, schema commit, environment pins, archive hash.
06 · The release gate

What the release owner actually runs

Valid once the sibling checkout sits exactly at the pin and the locked Python env is installed. Record the output — both commits and the archive hash — with the candidate evidence.
# 1 · generate + validate + prove, sandboxed
./scripts/run_integration_tests.sh --offline --schema-dir ../agent-life-data-format

# 2 · confirm the committed fixture matches what HEAD reproduces
./scripts/run_integration_tests.sh --check --offline --schema-dir ../agent-life-data-format
The gate is these two read-only commands — never --regenerate-fixture.
